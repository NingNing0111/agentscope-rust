# Feature Specification: AgentScope Rust 模块化使用文档

**Feature Branch**: `018-usage-docs`

**Created**: 2026-08-01

**Status**: Draft

**Input**: User description: "为rust重构的agentscope 编写详细的使用文档，要分模块介绍。，根目录 docs"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 新用户快速上手 (Priority: P1)

一名具备 Rust 基础、从未接触过 AgentScope 的开发者，希望在本地环境中从零开始，完成依赖引入、模型服务配置，并运行起第一个能对话的 Agent（含工具调用），从而确认该框架满足其需求。

**Why this priority**: 快速上手是文档的第一价值入口。如果新用户无法在合理时间内跑通第一个 Agent，后续所有模块文档都不会被阅读。这是整个文档体系的 MVP。

**Independent Test**: 仅交付本故事（快速上手指南 + 索引页）即可独立验证：一位新用户按照文档步骤操作，能够在干净环境中成功运行一个流式对话 Agent，并看到预期的终端输出。

**Acceptance Scenarios**:

1. **Given** 用户已安装 Rust 工具链且拥有有效的模型服务 API Key，**When** 用户按照快速上手文档逐步操作，**Then** 用户能在 30 分钟内运行起第一个可对话的 Agent 并收到模型响应。
2. **Given** 用户未配置必需的 API Key，**When** 用户运行示例，**Then** 文档中说明了会出现的错误提示及对应的配置方法（环境变量名、配置文件位置）。
3. **Given** 用户完成了第一个 Agent，**When** 用户想继续深入某个能力（如工具调用或记忆），**Then** 索引页能将其引导至对应模块文档。

---

### User Story 2 - 按模块查阅使用文档 (Priority: P2)

一名正在基于 AgentScope Rust 开发应用的开发者，需要使用某个具体能力（如工具系统、记忆、RAG、沙箱），他打开对应模块的文档，了解该模块的核心概念、主要公开类型、典型用法模式，并复制一个可运行的代码示例作为起点。

**Why this priority**: 这是文档体系的主体，覆盖用户日常开发中最高频的需求——"这个模块怎么用"。它独立于快速上手：即使快速上手尚未撰写，单模块文档也对已开始使用框架的开发者有直接价值。

**Independent Test**: 任选一个模块（如 Tool System），只交付该模块文档即可验证：开发者仅依据该文档，能够注册一个自定义工具并让一个 Agent 成功调用它，无需阅读源码。

**Acceptance Scenarios**:

1. **Given** 文档已覆盖某模块，**When** 开发者阅读该模块文档，**Then** 他能了解到该模块的核心概念、主要公开类型及其职责，无需翻阅源码。
2. **Given** 某模块文档中包含代码示例，**When** 开发者将示例复制到自己的工程中，**Then** 示例能够编译并按文档描述的行为运行。
3. **Given** 开发者使用了某模块暂不支持的能力，**When** 他查阅该模块文档，**Then** 文档明确标注了该能力为 unsupported 及其返回的错误类型，而非让他误以为可用。
4. **Given** 每个已实现的用户可见模块，**When** 用户浏览文档索引，**Then** 每个模块都有对应的文档入口，且文档间通过链接相互引用相关模块。

---

### User Story 3 - Python AgentScope 用户迁移参考 (Priority: P2)

一名熟悉 Python 版 AgentScope 的开发者，需要将既有应用迁移到 Rust 版本。他通过迁移参考文档了解两个版本之间的 API 对应关系、行为差异、各模块的兼容性等级（L1-L4），以及已知的兼容性偏差。

**Why this priority**: 项目宪法将"与 Python 参考实现的可观察兼容性"作为核心目标，迁移用户是该项目区别于一般新框架的关键用户群。与 US2 独立：即使迁移指南尚未撰写，模块使用文档仍然完整可用。

**Independent Test**: 仅交付迁移参考文档即可验证：一名 Python AgentScope 用户能根据对照表将其一个使用 ReActAgent + 工具调用的 Python 应用改写为等价的 Rust 代码，并理解两版之间的已知行为差异。

**Acceptance Scenarios**:

1. **Given** 用户熟悉 Python 版的某个 API，**When** 他查阅迁移参考，**Then** 能找到对应的 Rust API 名称、所在模块及用法示例。
2. **Given** 某模块存在已记录的兼容性偏差，**When** 用户查阅该模块的迁移说明，**Then** 偏差内容、原因和影响被明确列出，与兼容性矩阵保持一致。
3. **Given** 用户想了解某模块可以依赖到何种兼容程度，**When** 他查阅文档，**Then** 每个模块都标注了当前的兼容性等级（L1-L4）及该等级的含义。

---

### User Story 4 - 端到端场景教程 (Priority: P3)

一名已完成快速上手的开发者，想实现一个完整场景（如带长期记忆的会话、基于本地知识库的检索增强问答、多轮流式工具调用），他按照场景教程逐步构建，最终得到一个可运行的完整应用。

**Why this priority**: 场景教程是模块文档的横向串联，提升深度使用体验，但不构成使用框架的必经路径——用户完全可以仅凭模块文档自行组合。因此优先级最低。

**Independent Test**: 任选一个场景教程独立验证：用户按教程操作能得到一个可编译、可运行、行为符合教程描述的完整示例应用。

**Acceptance Scenarios**:

1. **Given** 场景教程覆盖的场景（如 RAG 问答），**When** 用户按教程完成所有步骤，**Then** 得到的应用能按教程描述运行（如对本地文档集进行检索增强问答）。
2. **Given** 教程依赖真实模型服务，**When** 用户阅读教程前置条件部分，**Then** 所需凭据、数据准备和预期成本被明确说明。

---

### Edge Cases

- 模块 API 在后续迭代中发生变化时，文档可能与代码脱节 → 文档中的代码示例必须可通过编译验证（复用 examples/ 或 doctest 机制），使过期示例能被 CI 发现。
- 用户按照文档配置了错误的凭据/环境变量名 → 文档中的配置项名称必须与代码实际读取的名称逐一核对一致。
- 文档宣称支持某能力但实际返回 `UnsupportedFeature` → 文档与兼容性矩阵必须交叉核对，禁止文档层面的"伪兼容"（宪法第五条在文档层面的延伸）。
- 用户环境中缺少可选依赖（如本地向量检索所需的特性开关）→ 模块文档必须说明可选能力的启用前提。
- docs/ 目录下已存在与本次工作无关的内容（如 `superpowers/`）→ 文档组织不得破坏既有内容。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 文档 MUST 位于仓库根目录 `docs/` 下，且不得破坏该目录中已存在的无关内容。
- **FR-002**: `docs/` 下 MUST 有一个索引入口文档，列出全部模块文档、推荐阅读顺序，并提供快速上手与迁移参考的导航。
- **FR-003**: 文档 MUST 提供快速上手指南，覆盖：环境准备、依赖引入、模型服务凭据配置（环境变量名称与代码实际读取值一致）、创建并运行第一个流式对话 Agent。
- **FR-004**: 文档 MUST 为每个已实现的用户可见能力模块提供独立的模块文档。模块清单至少覆盖：基础类型与消息模型（types/message）、事件与流式（event/streaming）、模型抽象（model）、DashScope Provider、工具系统（tool）、Agent 系统（agent）、记忆（memory）、会话管理（session）、RAG（embedding/rag/turbovec）、工作空间（workspace）、技能（skill）、沙箱（sandbox）。
- **FR-005**: 每篇模块文档 MUST 采用统一结构，至少包含：模块概述（解决什么问题）、核心概念与主要公开类型、快速示例（可运行代码）、关键用法模式、不支持的能力与已知限制。
- **FR-006**: 文档中出现的所有代码示例 MUST 是可编译验证的：或直接引用仓库中受 CI 编译约束的示例文件，或以其他可自动化校验的形式存在，确保 API 变更后过期示例能被发现。
- **FR-007**: 每篇模块文档 MUST 标注该模块当前的兼容性等级（L1-L4）及已知兼容性偏差（如有），且与兼容性矩阵的记录保持一致；MUST NOT 宣称支持实际返回 `UnsupportedFeature` 的能力。
- **FR-008**: 文档 MUST 提供 Python → Rust 迁移参考，包含主要公开 API 的对照（Python 类/函数名 → Rust 类型/trait/函数名）与行为差异说明。
- **FR-009**: 文档 MUST 提供至少一个端到端场景教程，串联多个模块（如 RAG 问答、带记忆的会话），且教程产物可编译运行。
- **FR-010**: 文档 MUST 面向框架使用者撰写，MUST NOT 包含仅与内部实现相关的细节（内部数据结构、私有算法等）；架构性说明仅限用户可观察的行为语义（如事件顺序、取消行为）。
- **FR-011**: 文档中所有配置项（环境变量名、参数名、默认值）MUST 与代码中的实际定义核对一致。
- **FR-012**: 文档 MUST 采用中英双语组织：索引入口为中英双语，每个模块文档、迁移参考、场景教程均提供中文与英文两个版本（双文件），同一内容的双语版本 MUST 保持结构一致、信息等价；任一语种版本更新时 MUST 同步更新对应版本。

### Key Entities *(include if feature involves data)*

- **文档站点（docs/）**: 仓库根目录下的文档集合，由索引入口和若干模块文档、迁移参考、场景教程组成，Markdown 格式，随仓库版本化。
- **模块文档（Module Doc）**: 描述单个能力模块的使用文档，包含概述、概念、示例、用法模式、兼容性标注，与对应 crate/模块一一关联。
- **代码示例（Code Example）**: 文档中引用的可运行代码，与仓库 examples/ 或编译校验机制关联，作为文档正确性的可验证锚点。
- **兼容性标注（Compatibility Annotation）**: 模块文档中的兼容性等级（L1-L4）与偏差记录，引用兼容性矩阵为权威来源。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 一名具备 Rust 基础的新用户仅依据快速上手文档，能在 30 分钟内（不含 Rust 工具链安装时间）从零运行起第一个可对话的 Agent。
- **SC-002**: 100% 已实现的用户可见能力模块（FR-004 清单）拥有对应的模块文档，索引中无悬空链接。
- **SC-003**: 文档中 100% 的代码示例通过编译验证（在文档交付时的代码版本上）。
- **SC-004**: 每篇模块文档包含至少 1 个端到端可运行示例，覆盖该模块的核心使用路径。
- **SC-005**: 文档与兼容性矩阵零冲突：不存在文档宣称可用、但实际返回 `UnsupportedFeature` 的能力，也不存在文档未标注的已知兼容性偏差。
- **SC-006**: Python 迁移用户能依据迁移参考，在不阅读 Rust 源码的情况下，将一个使用 ReActAgent + 工具调用的 Python 应用改写为等价 Rust 应用。
- **SC-007**: 抽查任一模块文档中的配置项（环境变量、参数默认值），与代码实际定义 100% 一致。
- **SC-008**: 每篇模块文档、迁移参考与场景教程均同时存在中文与英文版本，双语版本章节结构一一对应，无单语种缺失或内容漂移。

## Assumptions

- 文档格式为 Markdown，直接存放于仓库 `docs/` 目录随代码版本化；不引入独立的文档站点生成器（如 mdBook、Docusaurus），除非后续另行决策。
- `docs/` 目录已存在，其中既有内容（如 `superpowers/`）与本次工作无关，保持原样。
- 目标读者是具备 Rust 基础知识的开发者；文档不以 Rust 教学为目的。
- 文档中的示例以 DashScope 作为默认模型 Provider（当前唯一已实现的 Provider），并说明如何替换为自定义 Provider。
- 文档内容基于当前已实现的 Feature 001-017 范围；未实现的模块（Multi-agent、Distributed runtime）仅在索引中标注为"规划中"，不撰写使用文档。
- 场景教程默认使用真实模型服务凭据，但快速上手文档同时说明 Mock/测试替代方案的存在（对应测试基础设施文档）。
