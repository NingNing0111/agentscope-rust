# Feature Specification: Agent 运行时状态注入系统

**Feature Branch**: `026-runtime-state-injection`

**Created**: 2026-08-04

**Status**: Draft

**Input**: User description: "python版本的agentscope在项目根目录下，参考其实现，设计并实现任务调度能力，给agent工具"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Agent 通过统一注入管线感知当前时间 (Priority: P1)

开发者使用本库构建的 Agent 在长时间多轮对话中，能够感知"现在是什么时间"。当会话刚开始、上下文被压缩后，或距上次注入已超过配置的时间间隔时，Agent 的上下文中会追加一条包含当前时刻及其时区标注的提示块，使 Agent 能正确理解"今天""明天""三小时后"等相对时间表达，并在跨天任务中保持时间方位感。整个过程无需开发者编写任何时间处理代码。

**Why this priority**: 时间感知是"运行时状态注入"中最通用、最高频的能力——几乎所有长任务（定时任务、跨天跟进、日志时间戳）都依赖它；且它完全独立于既有任务注入，可单独构成可交付的 MVP。它也是 Python `_inject_runtime_state` 三个维度中最先评估、判断逻辑最独立的一个。

**Independent Test**: 使用默认配置构建 Agent 并执行一次带时间字段的回复，验证注入的提示块包含当前时刻与时区标注；连续快速触发多次回复，验证仅在首次（或超过配置间隔）注入；手动清除上下文后再次回复，验证重新注入。

**Acceptance Scenarios**:

1. **Given** 一个默认配置的 Agent，**When** 其开始第一次回复，**Then** 上下文中追加一条运行时状态提示块，其中包含当前时刻（按配置的格式与时区呈现）及对应时区标注
2. **Given** Agent 已注入过一次时间，**When** 距上次注入不足配置的时间间隔（默认 0.5 小时）内再次回复，**Then** 不重复注入时间字段
3. **Given** Agent 上下文中的时间提示块已被上下文压缩移除，**When** Agent 开始新一轮回复，**Then** 重新注入当前时间，保证 Agent 不会依据过期时间判断
4. **Given** 配置的时区在会话中途被修改，**When** 触发新的时间注入，**Then** 注入文本携带新的时区标注，且 Agent 仍能正确计算与上次记录时间之间的流逝时长

---

### User Story 2 - 未完成任务提醒纳入统一注入管线 (Priority: P2)

开发者依赖 Agent 在长会话中持续推进未完成的任务清单（已在既有特性中通过 Task 工具创建）。当存在进行中或待处理任务、而当前上下文中任务工具的调用痕迹已被压缩移除时，Agent 上下文中被注入一条提醒，说明进行中与待处理任务的数量并指引查看任务清单。该提醒从既有的独立实现升级为统一注入管线中的一个维度，注入文本、来源标识、感知检测行为均与既有实现保持一致，不破坏既有会话行为。

**Why this priority**: 这是既有能力（任务维度提醒）向新架构平滑迁移的保底项——保证统一管线落地后，已上线且被测试覆盖的任务提醒行为不回归。没有它，统一管线重构会破坏 024 已交付的兼容行为。

**Independent Test**: 复用既有任务提醒测试场景（未完成任务 + 上下文无任务工具痕迹 → 注入提醒；已感知或无未完成任务 → 不注入），验证升级到统一管线后全部通过，且注入文本与来源标识与升级前逐字节一致。

**Acceptance Scenarios**:

1. **Given** Agent 存在进行中或待处理任务，且上下文中既无任务工具调用痕迹、也无先前的任务提醒，**When** Agent 开始新一轮推理，**Then** 统一管线注入任务提醒字段，文本格式（进行中/待处理数量 + TaskList 指引）与升级前一致
2. **Given** Agent 上下文中存在任务工具调用痕迹或先前的任务提醒，**When** 新一轮推理开始，**Then** 不注入任务提醒，避免每轮冗余提示
3. **Given** 所有任务均已完成，**When** 发生上下文压缩或新一轮推理，**Then** 不注入任何任务提醒
4. **Given** 同一轮注入中同时满足时间与任务两个维度的注入条件，**When** 注入发生，**Then** 两个字段被组装进同一条提示块，而非产生两条提示块

---

### User Story 3 - 上下文用量预警注入 (Priority: P3)

开发者在长对话中希望 Agent 在上下文即将接近压缩阈值前主动感知并采取行动（例如提前总结、精简回答）。当一次回复刚开始、当前输入 token 数已落入压缩阈值减去缓冲比例所对应的窗口内时，Agent 上下文中被注入一条提示，说明当前上下文所含 token 数与触发压缩的阈值，让 Agent 有机会在压缩发生前收敛回答。该维度独立于时间与任务维度评估，不与其他维度互相影响。

**Why this priority**: 这是 Python 参考实现三维注入中的第三个维度，用于提升超长对话的稳健性。它依赖模型上下文尺寸与既有压缩阈值配置，但与时间/任务维度评估完全解耦，可在前两个维度稳定后独立落地。

**Independent Test**: 配置一个较小的上下文尺寸与压缩触发比例，构造一次 token 数落入预警窗口的回复，验证注入上下文用量字段；配置 token 数远离阈值时，验证不注入。

**Acceptance Scenarios**:

1. **Given** 上下文配置已启用压缩且设置了触发比例，**When** 一次回复开始时输入 token 数已超过（触发比例 − 缓冲比例）所对应的阈值，**Then** 注入上下文用量字段，说明当前 token 数与触发压缩的阈值 token 数
2. **Given** 一次回复开始时输入 token 数未落入预警窗口，**When** 回复开始，**Then** 不注入上下文用量字段
3. **Given** 回复已进入后续迭代（非首轮），**When** 迭代继续，**Then** 不重新评估上下文用量注入，避免每轮重复注入
4. **Given** 时间与任务维度均不满足注入条件，**When** 仅上下文用量维度满足，**Then** 仅注入上下文用量字段，且不因额外字段的缺失而跳过注入

---

### User Story 4 - 注入系统可配置并与事件管线集成 (Priority: P4)

开发者能够通过一份统一的配置控制运行时状态注入的全部行为：总开关、时区与时间格式与最小注入间隔、上下文缓冲比例、注入模板、注入来源标识、用于抑制任务注入的任务工具名列表、自定义附加字段，以及是否在注入时对外发出提示块事件。配置项缺失时使用与 Python 参考实现一致的默认值；注入始终以非系统提示词的方式追加到持久上下文，保证提示缓存有效。

**Why this priority**: 这是统一注入系统的"配置化与可观测性"收尾——让前三个维度的行为可被开发者按场景调整，并通过事件让外部系统感知注入发生。它依赖前三个维度已接入同一管线，因此优先级靠后。

**Independent Test**: 逐项修改配置（总开关关闭、自定义模板、自定义来源标识、自定义附加字段、关闭事件发射），验证对应行为变化；订阅事件流，验证注入发生时发出提示块事件。

**Acceptance Scenarios**:

1. **Given** 开发者关闭注入总开关，**When** Agent 满足任意维度的注入条件，**Then** 不注入任何运行时状态，行为退化为纯推理-行动循环
2. **Given** 开发者自定义注入模板与来源标识，**When** 注入发生，**Then** 提示块按自定义模板渲染、携带自定义来源标识，且感知检测基于新的来源标识工作
3. **Given** 开发者配置自定义附加字段，**When** 任意维度触发注入，**Then** 附加字段被一并组装进同一条提示块；仅配置附加字段但无任何维度触发时，**Then** 不产生注入
4. **Given** 开发者开启事件发射，**When** 注入发生，**Then** 事件流中发出提示块事件，携带回复标识、块标识、来源与提示内容；关闭后不再发出

---

### Edge Cases

- 机器时钟向后回拨导致记录时间晚于当前时间时，必须重新注入时间，保证 Agent 时间感知正确
- 注入文本中记录的时间因时间格式变更而无法解析时，必须重新注入时间而非沿用错误判断
- 会话中途修改时区后，对上次记录时间的流逝计算必须基于记录时间旁的时区标注，而非当前配置时区
- 任务提醒、时间、上下文用量三个维度各自独立判断；任一维度满足即触发一次注入，全部不满足则零注入
- 注入不得修改系统提示词，必须以非系统提示词的方式追加到持久上下文，保证提示缓存不失效
- 注入总开关关闭时，三个维度均不评估、不注入、不发事件，且任务工具注册行为不受影响（与既有配置解耦）
- 上下文压缩移除提示块后，感知检测应基于剩余上下文重新判断，各维度按各自规则重新注入
- 自定义模板未包含运行时状态占位符时，配置校验必须拒绝该模板，防止注入字段被静默丢弃

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Agent 必须具备一个统一的运行时状态注入管线，在每次回复开始时评估时间、未完成任务、上下文用量三个维度，将命中的维度组装为一条非系统提示词的提示块追加到持久上下文；三个维度各自独立评估，任一命中即注入一次，全部未命中则零注入
- **FR-002**: 时间维度必须支持可配置的时区、时间格式与最小注入间隔（默认 UTC、`%Y-%m-%dT%H:%M:%S`、0.5 小时）；当上下文无已记录时间、记录时间无法按当前格式解析、距上次记录超过间隔或记录时间晚于当前时间（时钟回拨）时注入，否则不注入
- **FR-003**: 时间注入必须同时携带当前时刻与其时区标注；对上次记录时间的流逝计算必须基于记录时刻旁的时区标注，保证会话中途修改时区后计算依然正确
- **FR-004**: 任务维度必须保留既有行为——存在进行中或待处理任务且上下文既无任务工具调用痕迹（按可配置的任务工具名列表匹配）也无先前的任务提醒时，注入任务提醒字段，文本说明进行中与待处理任务数量并指引查看任务清单；任务注入字段与来源标识与既有实现保持逐字一致
- **FR-005**: 上下文用量维度必须支持可配置的缓冲比例（默认 0.2）；仅在每次回复的首轮迭代评估，当输入 token 数超过（压缩触发比例 − 缓冲比例）× 模型上下文尺寸时，注入说明当前 token 数与触发压缩阈值 token 数的字段
- **FR-006**: 注入系统必须提供统一配置，至少包含：总开关、时区、时间格式、时间间隔、上下文缓冲比例、注入模板、注入来源标识、任务工具名列表、自定义附加字段、事件发射开关；各配置项默认值与 Python 参考实现一致
- **FR-007**: 注入模板必须包含运行时状态占位符；模板缺失该占位符时配置校验必须拒绝，防止注入字段被静默丢弃
- **FR-008**: 注入来源标识必须作为感知检测的固定依据，用于在上下文中识别先前注入；任务维度与时间维度复用该来源标识检测先前注入，且任务工具调用（命中可配置的任务工具名列表）视为已感知任务
- **FR-009**: 自定义附加字段必须被组装进每次注入的同一提示块，但单独配置附加字段不得触发注入
- **FR-010**: 注入发生时，若事件发射开关开启，必须发出提示块事件，携带回复标识、提示块标识、来源与提示内容；关闭后不得发出
- **FR-011**: 注入总开关关闭时，三个维度均不得评估与注入，不得发出提示块事件，行为退化为纯推理-行动循环；总开关与任务工具注册开关相互独立
- **FR-012**: 注入必须以追加到持久上下文的方式实现，不得修改系统提示词，以保证提示缓存有效；被压缩移除后按各维度规则重新注入
- **FR-013**: 当时间、任务、上下文用量中多个维度同时命中时，字段必须组装进同一条提示块，注入顺序与 Python 参考实现一致（时间、任务、上下文用量，附加字段最后），保证提示缓存命中率
- **FR-014**: 配置校验必须拒绝非法值：时间格式无法往返完整时间戳、间隔为负、缓冲比例超出 [0,1]、缓冲比例大于等于压缩触发比例、模板缺失占位符；拒绝时返回结构化配置错误，不得静默接受。时区名无效时不拒绝配置，运行时解析失败回退 UTC（对齐 Python 参考实现 `_resolve_timezone` 行为）

### Key Entities *(include if feature involves data)*

- **InjectionConfig（注入配置）**: 控制运行时状态注入的配置集合——总开关、时区、时间格式、时间间隔、上下文缓冲比例、注入模板、注入来源标识、任务工具名列表、自定义附加字段、事件发射开关；与 Agent 构建配置绑定，随 Agent 生命周期生效
- **Runtime State Hint（运行时状态提示块）**: 追加到持久上下文的提示块，携带注入来源标识与渲染后的提示文本；一次注入可包含时间、任务、上下文用量、附加字段中的一个或多个字段
- **Injection Source（注入来源标识）**: 用于感知检测的固定标识，在上下文中识别先前注入；任务维度同时将任务工具调用视为感知证据
- **Hint Block Event（提示块事件）**: 注入发生时对外发出的事件，携带回复标识、提示块标识、来源与提示内容，供外部系统观察注入行为

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 时间维度在满足注入条件（首次回复、压缩后、超过间隔、时钟回拨）时注入比例为 100%，不满足条件时注入次数为 0
- **SC-002**: 既有任务提醒行为在升级到统一管线后不回归——Feature 024 的全部任务提醒测试场景通过率为 100%，且注入文本与来源标识逐字节一致
- **SC-003**: 上下文用量维度在 token 落入预警窗口时注入比例为 100%，未落入窗口或非首轮迭代时注入次数为 0
- **SC-004**: 各配置项（总开关、时区、时间格式、时间间隔、缓冲比例、模板、来源标识、任务工具名列表、附加字段、事件开关）逐一验证生效，非法配置 100% 被结构化拒绝
- **SC-005**: 同一回复中多维度同时命中时，字段组装进同一条提示块（而非多条）的比例为 100%
- **SC-006**: 注入开启时事件发射比例为 100%、携带字段齐全；注入关闭或事件开关关闭时发射次数为 0
- **SC-007**: 启用注入后，系统提示词在任何注入场景下均保持不变，提示缓存不因注入失效

## Assumptions

- 特性范围经确认限定为"完整运行时状态注入"：实现 Python 参考实现 `_inject_runtime_state` 的时间、任务、上下文用量三个维度及完整配置，并作为既有任务提醒注入的泛化升级；不包含把任务分发给 SubAgent 执行的分发调度机制
- 既有任务维度注入（Feature 024）的注入文本、来源标识、感知检测行为作为兼容基线，升级过程中必须保持逐字一致，不引入行为回归
- 配置项命名、默认值、注入字段文本与 Python `InjectionConfig` 及 `_inject_runtime_state` 参考实现保持一致，以支撑黄金快照/差分测试
- 注入每次回复开始时评估一次；任务提醒在上下文压缩移除痕迹后于后续迭代可重新触发（与既有实现一致），时间与上下文维度按各自规则评估
- 时间维度依赖稳定的系统时钟与标准时区数据库；Rust 侧以既有时钟库能力实现时区解析与格式化
- 上下文用量维度依赖模型上下文尺寸与 token 计数能力，二者已在既有实现中提供
- 注入事件复用既有提示块事件类型，不新增事件类型
